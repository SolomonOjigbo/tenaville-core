Launch blockers

These are the reasons a public launch should not be scheduled. Several also block a credible R1 pilot.

1

No staff mobile app

R1 requires native iOS/Android with offline capture, provisional receipts, sync state, device protection, low-data uploads and push. None exists. R1 exit criteria cannot be met.

2

Outbound messaging is not real

The logging provider reports success without contacting WhatsApp, SMS or email. The log can say “sent” when nobody was messaged. No scheduler runs rent, lease or maintenance reminders.

3

Subscription billing has no gateway

Invoices and manual payment recording exist. BILL-2's gateway, checkout and subscription receipts do not. A new customer cannot pay Tenaville from the product.

4

Migration, opening balances and export are missing

No tenant/lease import, cutover balances, dry-run/rollback or organisation-wide export. Pilot exit criteria require reconciliation and export.

5

Production operations are absent

No staging/deployment configuration, error tracking, uptime or job monitoring, backup/restore drill, incident process, support channels or security testing.

6

Legal and compliance gates are open

Name/trademark, NDPA privacy, client-money treatment, WhatsApp policy, payment licensing and consumer transparency all remain unresolved.

7

P0 scope gaps remain

Session/device management, property photos, lease handover/termination, full deposit lifecycle, ledger evidence, maintenance media/notifications and the full operational report set are partial or absent.

Evidence and documentation drift

Reviewed

23 SQL migrations · 24 pgTAP files / 458 assertions · 58 web pages · two API route handlers · 153 core tests · 98 web tests · CI quality and isolation gates · compliance register · operations README · PRD and R1 exit criteria · live hosted checks across rent, statements, maintenance, comms, documents and billing.

Release records are stale

README still says “pre-implementation … no feature code yet”; backlog mapping says 8 done / 120 todo and “no user interface exists”; traceability says 0 of 194 requirements done. An external reviewer, pilot agency or investor cannot rely on the repository's own status. Refreshing it is part of launch readiness.

Recommended path

  1. Decide launch scope. Build mobile R1, or re-baseline to a web-only pilot with contractual scope removal. Do not claim R1 complete while mobile is absent.
  2. Make messaging real. Wire production providers, add scheduled reminder jobs, label logging honestly until then, and enforce consent/rate limits.
  3. Close billing. Add a licensed Nigerian subscription payment path and gateway receipts, or launch invoice-only by explicit commercial decision.
  4. Close migration and export. Tenant/lease import, opening balances, dry-run/rollback and organisation export are pilot exit criteria.
  5. Make production operable. Staging, deploy pipeline, error/uptime/job monitoring, backup restore drill, incident response, support and status page.
  6. Clear the legal register. Name, privacy/NDPA, client money, messaging policy, payment licensing and consumer copy.
  7. Test adversarially. Pen test, dependency cadence, load test, browser E2E and accessibility audit.
  8. Run a controlled pilot. Three agencies, a full month-end, offline/payment/receipt/statement acceptance and documented exceptions before a public decision.

Decision: no public launch. Conditional web-only pilot only after the operational, messaging, billing, migration, security and legal gates above are closed or formally accepted as pilot exceptions.
